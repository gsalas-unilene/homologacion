# SIGA best-match selection and final Excel

Objective: for each of the 1085 homologated MINSA rows (non-`sin_equivalente` plus all suture rows) choose the best SIGA catalog code among the options captured from the CBSO search box, and write the final Excel with every extra option in additional columns.

Inputs (git-ignored, in `salida/`): `homologacion.csv` (MINSA rows and tiers), `queries.json` (row order -> cleaned query), `siga_raw.json` (first pass: one record per unique query `{q, status, rows:[[code, description]]}`), `siga_raw2.json` (second pass: `{q, v, status, total, rows}` for the 184 queries without an exact match, one record per search variant: synonym-normalized text, text without the size tail, material+calibre prefix, and a `DE` toggle; up to 3 pages of 100 rows per search).

Why: pass 1 left 897 exact matches, 27 single non-exact, 31 multiple and 130 without result. The SIGA description is usually the MINSA description with different wording (NYLON/NAILON, C/2A vs C/DOBLE AGUJA, N° removed, CC/CR abbreviations), so the best option must be chosen by attributes, not by position (SIGA lists results by code, not by relevance).

Scope: `src/homologador/siga.py` (candidate union, scoring, estado), `siga_excel.py` at repo root (builds the xlsx; `openpyxl` only through `uv run --with openpyxl`, no project dependency), tests with a small committed fixture, README section. Not in scope: more scraping, changing the homologation tiers.

Rules: suture rows reuse `atributos.parse` (material, calibre, curvature, point, mm, cm, double needle) on both texts; non-suture rows reuse the head-word/qualifier and number-unit logic of `generico.py`. Normalized-equal description = `exacto`. Choose the best candidate with all core attributes equal (material family, calibre, curvature, point, single/double needle) and the nearest needle and thread lengths = `mejor_coincidencia`, with the differences listed. Core attribute differences = `aproximado`. Two or more candidates tied at the top = `ambiguo` (all listed). None = `sin_resultado`. Never pick a different material, calibre or single/double needle as the main code without marking `aproximado`.

Output columns (in addition to the tier columns): `SIGA_estado`, `SIGA_puntaje`, `SIGA_codigo_1`, `SIGA_descripcion_1`, `SIGA_diferencias`, `SIGA_codigo_2..5` (next best options, ranked), `SIGA_alternativas` (`code: description | ...` for the options shown), `SIGA_total_opciones`.

## Evidence and limitations
- G1 (bfba5cd): `src/homologador/siga.py` (`candidatos` unions pass 1 and every variant, deduped by code with the sources; `clave`; `elegir`). Suture rows use the existing attribute parser on both texts (`atributos_texto`): core = family, calibre, curvature, point, single/double needle plus color/construction; length differences rank the options (nearest needle, then thread) and are listed. Non-suture rows use `generico` (numbers+units, head word, qualifiers) plus word coverage. Fixture `tests/fixtures/siga_muestra.json`: 30 real records (exact, NYLON/NAILON, C/2A vs C/DOBLE AGUJA, nearest length, ties, no result, catheter, gloves, blade, needle...). Parser fixes found while reading real SIGA wording (each with a failing test first): `2C/A` is a double needle, the vulgar fraction sign, `CORTE INVERTIDO` = reverse cutting, half sizes (`Nº 7 1/2` is not `Nº 7`). Rules tuned by reading ~60 real multi-option rows: a multipack/spool/needle-less request never takes a needled option as main (curvature class weight), stated attributes SIGA lacks are not mismatches but the plainer option ranks first, a MINSA name without calibre can never be `mejor_coincidencia`, non-suture options must cover 75% of the MINSA words, puntaje is 100 only for equal text.
- G2: `siga_excel.py` (+ README section). `uv run --with openpyxl python siga_excel.py` -> 1085 rows: exacto 900, mejor_coincidencia 121, aproximado 16, ambiguo 34, sin_resultado 14; 444 rows with 2+ options. First pass -> new: sin_resultado 130 -> mejor_coincidencia 77, exacto 5, ambiguo 22, aproximado 12, still sin_resultado 14; multiple 31 -> mejor_coincidencia 20, ambiguo 7, aproximado 4; unico 27 -> mejor_coincidencia 24, ambiguo 3; exacto 897 -> exacto 895, ambiguo 2 (two codes with the same text).
- Checks: `FASTMCP_ENV_FILE=NUL uv run python -m unittest discover -s tests`: see the final report (the xlsx test needs `uv run --with openpyxl`; it passes there and is skipped otherwise).
- Limitations: 14 sin_resultado are real gaps in SIGA (bare `VICRYL O DEXON`, polyglycolic monofilament, polyester braided without color, polyethylene). A few `aproximado` rows have a low puntaje because SIGA returned only unrelated products (fistula needle -> venoclysis extension): filter by `SIGA_puntaje`. Barbed sutures go through the non-suture comparison (no material in the MINSA name). `ambiguo` includes rows where the MINSA name omits the thread length and several lengths tie.
