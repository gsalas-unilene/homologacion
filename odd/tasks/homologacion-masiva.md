# Bulk homologation: MINSA -> own products (items.csv)

Objective: produce, for every row of `items/items_minsa.csv` (23005 rows), the best matching own product from `items/items.csv` (22668 rows), with a confidence tier, as a reviewable CSV. Suture rows use attribute re-ranking; the rest use a generic strategy.

Why: the user needs the full MINSA catalog homologated to their own products. Evidence: own catalog is 96% sutures (21832 of 22668), 836 non-suture items across 13 groups (Linea Xterie, mallas, plasticos, guantes, sondas...). MINSA is mostly screws, plates, tubes, catheters (about 1000 start with SUTURA), so most MINSA rows are expected to have no equivalent. Prototype (scratchpad, 50 sampled suture rows): exact candidate at rank 1 went from 12 to 31 of 34 when re-ranking the top-30 vector candidates by parsed attributes (material, gauge, needle curvature, needle type, mm, cm). 10 of 50 rows were not parsed (rules missing).

Scope: new module(s) under `src/homologador/`, a CLI entry (`homologar.py` at repo root, like `poblar_catalogo.py`), tests, README section. Reads the active LanceDB catalog directly (not through MCP tools). Output `salida/homologacion.csv` (git-ignored). Not in scope: changing the MCP tools, reindexing, any clinical equivalence claim, push or PR.

Constraints: no embedder at lookup (reuse stored vectors, L2); agent tools never read the real `.env`; tiers are candidates for human review, not clinical validation; conventional commits, no AI attribution (user CLAUDE.md); TDD mode: strict enabled by session config (source: user CLAUDE.md), runner `uv run python -m unittest discover -s tests` with `FASTMCP_ENV_FILE=NUL`.

Output columns: CodigoMed, NombreMed, Coditem, Item, Agrupador, tier (`probable`, `revisar`, `sin_equivalente`), distance, score, plus alt_2 and alt_3 Coditem. Tier rules: suture rows -> `probable` if material, gauge, curvature and needle type all equal; `revisar` if family matches but an attribute differs; non-suture rows -> `revisar` if L2 distance <= threshold and parsed numbers/units agree, else `sin_equivalente`; any row with distance > threshold -> `sin_equivalente`. Threshold chosen from the data (prototype: suture matches 0.17-0.31, an unrelated vaccine 1.05).

## Evidence and limitations
- H1 (ad058b6): `atributos.py` parses material, gauge, curvature, needle type, mm, cm, needle count (0/1/2). Over the 998 MINSA `SUTURA%` rows, unparsed counts fell from 168 material / 24 gauge (prototype) to 7 material / 9 gauge; the rest are bare names (`SUTURA CATGUT CROMICO`), barbed sutures and `MR 20` codes. Over 21832 own suture items: 109 material / 74 gauge unparsed (wire, collagen, veterinary names). `parse_item` also strips the trailing supplier code (SD, VE, CP...).
- H2 (3107bfb, f0401fb): `generico.py` compares number+unit tokens (`10 MM`, `2.5 ML`, `5 FR`, `N 12`) over the top-30 and ranks by (token mismatches, distance). Threshold MAX_DISTANCE = 0.35 from stored vectors: best attribute-exact suture candidate over 233 sampled rows p50 0.24, p95 0.32, max 0.42; nearest own item for 600 sampled non-suture rows starts at 0.275 (catheters, fistula needles: related) and unrelated neighbours (plates/screws to sutures) appear from 0.36.
- H3 (f0401fb): `homologar.py` (+ `clasificar.py`, README section). Deviation from the tier rule text: `probable` is kept at any distance (attributes vouch for it); the 0.35 limit applies to `revisar`. Non-suture rows with no number/unit agreement are `sin_equivalente` with empty candidate columns and the nearest distance.
- Checks: `FASTMCP_ENV_FILE=NUL uv run python -m unittest discover -s tests`: 77 tests OK. `uv run python homologar.py --limit 200`: probable 4, revisar 2, sin_equivalente 194 (about 14 s). `--limit 2000`: probable 70, revisar 22, sin_equivalente 1908 (72 s, about 36 ms/row, so the full run should take about 14 min).
- Limitations: the first MINSA rows are mostly non-suture, so these counts are not representative; spot-checks are H4. Unit `G` conflates grams and gauge. Color, brand and sterilization are not compared. Items with a null `mat` (barbed, wire without word match) fall to the generic path.

## H5 non-suture recall (2026-10-05)
- Rename tier `exacto` to `probable` in code, tests, README, CSV and this document (earlier evidence lines were rewritten to the new name).
- Non-suture rows (not `es_sutura`: named SUTURA with a recognized material) are searched with a LanceDB prefilter `Agrupador != '01. SUTURAS'` (836 items). Suture-path rows are unchanged.
- Data (400 random non-suture MINSA rows, restricted nearest item): distance p10 0.50, median 0.68, max 1.22. Plausible matches with agreeing numbers sit at 0.28-0.45; junk with agreeing numbers starts at 0.47 (needle "N 21" -> blade "N 21", hand piece/burr -> gloves). Names without any number agree vacuously (lens -> mesh 0.59, tacrolimus -> gloves 0.63), so they keep the strict 0.35. New constant MAX_DISTANCE_RELAJADO = 0.45 for names with tokens.
- New tokens: glove/gown sizes (`TALLA S`, `NO ESTERIL S`), inches (`5/16 in`, `5/16"`, `1 1/2''`) as a separate unit never converted to mm, and `N 23 G` is a gauge, not also a size. Effect: gloves of a different size no longer agree, a 21 G hypodermic needle no longer matches a 21 G spinal needle of another length.
- Checks: `FASTMCP_ENV_FILE=NUL uv run python -m unittest discover -s tests`: 83 tests OK. Sample of 300 random non-suture MINSA rows (scratch script, seed 5): revisar 2, sin_equivalente 298 (the own non-suture catalog is small, so most rows truly have no counterpart). Targeted over all MINSA glove, aspiration tube and hypodermic needle rows: revisar 11 gloves + 6 tubes, sin_equivalente 131 gloves + 24 tubes + 36 needles.
- Limitations: nitrile gloves with size just beyond 0.45 (0.458-0.49) stay sin_equivalente; tubes written `5/16 X 7/16` without unit (own items use inch marks) and `7 mm X 11 mm` vs `5/16"` are not equated (no conversion); own catalog has no hypodermic needles, so those are correctly sin_equivalente.

## H6 keyword check (2026-10-05)
- `compatibles(nombre, item)` in `generico.py`, applied inside `elegir` (a rejected candidate is skipped, so the next compatible one can still win). Words are lower-noise 4-letter prefixes after a small stopword list (GUANTE/GUANTES, EXAMEN/EXAMINACION). Rules: the MINSA head word must appear in the item (or the item's head word in the name, for kits such as `SET DE ANESTESIA EPIDURAL CON AGUJA` vs `AGUJA EPIDURAL`); names without numbers or sizes need at least two shared words; contrastive qualifiers must not differ when both sides state one (UN/SIMPLE vs DOBLE vs TRIPLE lumen, ESTERIL vs NO ESTERIL, SIN vs CON POLVO, REINHALATORIA vs NO REINHALACION). No new dependencies.
- Measured on the 105 non-suture `revisar` rows of `salida/homologacion.csv` (H5 run), re-classified with the same restricted search: 87 kept, 18 dropped, no row changed candidate. Dropped: 4 tensiometer cuffs vs ID wristband; 5 central venous catheters (triple vs double lumen 4 Fr x13 and x8, 12 Fr; double vs triple 5.5 Fr; un lumen vs double 7 Fr); 2 reagents (triglyceride, antifungigram) vs traceability system; protein S kit vs swab; full-face respirator and wrist support vs exam gloves (size letter coincidence); dental mirror set vs bone wax; non-sterile gown vs sterile gown; rebreathing mask vs non-rebreathing mask; resuscitator bag vs oxygen mask. Reason for each is a head-word or qualifier mismatch; none looked like a good pair.
- Checks: `FASTMCP_ENV_FILE=NUL uv run python -m unittest discover -s tests`: 88 tests OK.
- Limitations: a catheter name without a lumen count still matches a double-lumen item (qualifier absent on one side); hydrogel/alginate dressings still match the gelifying-fiber dressing (shared head APOSITO, borderline by design); the stopword and qualifier lists are hand-made and will need extending as new products appear.
